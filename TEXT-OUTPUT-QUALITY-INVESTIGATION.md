### Key Discovery (15:30)

The model produces CORRECT text output when using:
- `mode: "turn_based"` (NOT full_duplex)
- `use_tts_template: true`

Examples:
- Session 1: "1+1=2。请问还有其他问题吗？"
- Session 2: "2."
- Session 3: "1+1=2。您还有其他问题需要咨询吗？"

The previous "garbage text" was caused by sending `messages` to full_duplex mode,
which is designed for audio-only input (rejects messages with "mode_mismatch").
Default mode is "full_duplex" (protocol.cpp:274).

## Interpretation

CANN, CPU, and the July 16 reference binary all fail with similar signatures.
The evidence does NOT isolate CANN as the root cause. The failure is in a
shared runtime path (prompt construction, modality routing, token-range
interpretation, model conversion, or sampling state machine).

Candidate root causes (under investigation):
1. Prompt/template mismatch with model expectation
2. Text/audio token vocabulary-range routing error
3. Model GGUF conversion metadata misalignment
4. Sampling state machine defaulting to TTS/audio branch
5. Chat template mode flag (`use_tts_template`) propagation error

**Changes 1-3 are UNCOMMITTED** — they exist in the working tree but not in any git commit.
They add `<|im_end|>` (token ID 151645) as a stop token in non-duplex mode, matching
the Python reference terminators `["<|tts_eos|>", "<|im_end|>", "</s>"]`.

**Risk assessment for changes 1-3:**
- `<|im_end|>` token ID 151645 is ≥ 150000, which is in the filtered range for
  `is_valid_tts_token` (line 6883) — but this filter applies to TTS text assembly,
  NOT to end-token detection, so the two paths don't conflict.
- `get_token_type()` returns NORMAL for `<|im_end|>` (no dedicated type),
  so `is_end_token()` checks `token == ctx->special_token_im_end` directly.
- In turn_based mode with correct text output, the model generates `</s>` (EOS)
  as the stop token — `<|im_end|>` is NOT being generated by the model in this mode.
  The `<|im_end|>` check is a safety net, not the primary stop mechanism.

**Change 4 (committed) provides:**
- `ws_cleanup_kv_cache_for_reuse`: Clear KV cache + reset n_past on disconnect
- `ws_finalize_context_reusable`: ACTIVE → DRAINING → REUSABLE state machine
- T2W drain fast-path for text-only sessions (advances generation counters)
- These are verified working: 10/10 sequential sessions PASS
